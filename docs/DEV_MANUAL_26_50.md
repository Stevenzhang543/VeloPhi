# Verity 26.50 开发手册

26.50 解决四件事：仿真时长不再有上限，从 t = 0 一直算下去；界面与全部教学内容提供中文、英文、德文三种语言；公式卡片和事件都能点开，看到推导和带当前数值的解题过程；求解器改用 Rust 编写，编译成 WebAssembly 在计算线程中运行，与 26.49 的 TypeScript 求解器逐位一致、速度明显更快。26.48、26.49 手册中的原则、阈值和决策（D1–D25）继续有效，本手册只写新增和修改的部分。26.51 在此基础上做自由度、引擎与公式库的扩展（见 `DEV_MANUAL_26_51.md`）。

两个版本的划分依据：26.50 先完成“地基”——无限时长要求记录和计算方式重做，三语言要求所有文字有统一的键，Rust 核心要求先证明与现有引擎逐位一致；这三件事做完之后，26.51 的新功能只需写一次（Rust 引擎、三语文本、无限时长记录）。

## 1. 版本目标

| 优先级 | 功能 | 要求 |
| --- | --- | --- |

## 2. 不做

本版不加新物理模型与新公式（26.51），不做触屏与无障碍（26.51），不做原生（非 WASM）桌面引擎（26.51 评估），不做电学插件（26.51 之后）。

## 3. 本版新增决策

**D26 无限时长：流式计算、检查点与确定性重算。** `settings.duration` 改为可选：`null` 表示不限时长（新场景默认），数值表示到该时刻停止；新增 `settings.stopAt`（可选：在第一次出现某类事件后再算 x 秒停止，例如“共速后 1 s”）。计算由“一次算完”改为“按需推进”：计算线程维持一个**前瞻窗口**（默认领先播放位置 20 s 仿真时间，或领先 3 s 墙钟时间，取较大者），窗口满了就暂停，播放头前进或用户请求“算到 t”时继续。记录分三层：(1) 热区——播放头附近和最新计算点附近的完整帧（每 Δt 一帧），按块（默认 1 s 一块）组织；(2) 检查点——每块开头的完整状态向量、当前模式与事件函数的武装状态（重新开始积分所需的一切）；(3) 摘要——每块每个观测量的最小值/最大值/首末值，用于长时间曲线。内存超出预算时丢弃最久未用的热区块，只保留检查点和摘要；需要时从检查点重算该块。**重算与第一次计算走完全相同的代码路径、从同一状态出发，因此逐位相同**（检查点保存的是精确状态，不是插值）。事件、阶段、能量账本辅助积分全程保留（体积很小）。结果指纹改为“滚动指纹”：每块一个 SHA-256，整体指纹是块指纹链的哈希；界面显示“截至 t 的指纹”。有限时长场景的指纹算法不变（与 26.49 相同）。公式识别按阶段增量进行：一个阶段结束即识别它，阶段内的卡片随时间更新。停止条件：用户停止、到达设定时刻或事件、或检测到“永久静止”（所有物体相对静止且无外力做功、无主动件，之后状态恒定，可以 O(1) 延伸）。

**D27 三语言：带类型检查的文本表，不用运行时编译。** 不引入 vue-i18n：它在运行时编译消息，需要放宽 Tauri 的内容安全策略，而我们的文本是静态的。新建 `src/i18n/`：`zh.ts` 为源表（嵌套对象），`en.ts`、`de.ts` 必须满足同一类型（TypeScript 检查缺键、多键）；`t(key, params)` 支持具名参数和复数（`{n}` 与 `plural`）；界面用响应式的当前语言。物理核心与公式层不写任何自然语言：错误、警告、事件说明、情形与条件都改为“消息键 + 参数”（例如 `{ key: 'warn.deepOverlap', params: { body: 'b1' } }`），由界面翻译。物理符号与 LaTeX 不翻译；术语表（`docs/i18n/GLOSSARY.md`）固定三种语言的物理术语（如 共速 / common velocity / gemeinsame Geschwindigkeit，劲度系数 / spring constant / Federkonstante），翻译以教材用语为准：德文参照德国高中（Sekundarstufe II）物理教材用语。数字格式随语言（德文小数逗号可选，默认跟随语言），单位符号不变。语言是应用设置，不写入场景文件；导出的 CSV/报告/课件用当前语言，也可在导出对话框单独选择。

**D28 公式详情：推导是数据，解题过程由数据生成。** 每条公式新增 `derivation`：一个步骤数组，每步包含 LaTeX 式子、说明文字的消息键（三语言）和依据（如“牛顿第二定律，沿斜面方向”“动能定理”“上一步代入”）。推导从情形的受力分析或守恒式出发，到公式结束；同一情形内的多条公式共享前几步（例如板块模型的 a₁、a₂ 都从各自的受力分析出发，t₁ 引用 a₁、a₂ 的结论）。**代入求解**不手写：由公式表达式树自动生成——先列出已知量（来自场景，带显示单位），再按表达式结构从内到外逐步代入、计算，每步写出数值结果，最后与仿真值比较；数值运算使用与卡片相同的格式化规则。**适用条件**逐条显示当前状态（成立 / 近似 / 不成立）与原因（例如“物块与木板仍在相对滑动：vₓ 差 = 1.23 m/s”）。**事件详情**：每种事件类型有一个说明模板——触发函数 g(t) 的定义（如共速事件 g = v₁ − v₂，离开事件 g = N），定位方法与精度（Illinois 法，|Δt| ≤ 10⁻¹² s），事件前后状态对比；碰撞事件额外给出碰撞方程（法向恢复、动量或冲量方程）与逐步代入的冲量计算，摩擦碰撞给出 Stronge 路径的分段（压缩、恢复、黏着/滑动）。详情界面是可停靠的面板（右侧或全屏阅读模式），可复制 LaTeX、导出为图片，在课件和报告中可选附带推导页。

**D29 Rust 核心与 WebAssembly 接口。** 新建 `engine/` 工作区（与 `src-tauri` 分开，避免把 Tauri 依赖带进 WASM）：`engine/verity-core`（`#![forbid(unsafe_code)]`，依赖仅 `serde`、`serde_json`）实现场景模型、编译、运动学、动力学、模式、事件、碰撞、积分器、投影、Moreau–Jean、变力表达式、流式记录与 SHA-256；`engine/verity-wasm`（`crate-type = ["cdylib"]`）只导出 C ABI 函数：`alloc/dealloc`、`run_create(scene_json) -> handle`、`run_advance(handle, budget_steps) -> status`、`run_take_delta(handle) -> (ptr,len)`、`run_rebuild_chunk(handle, chunk) -> (ptr,len)`、`run_free`，数据以与 D20 相同的二进制增量格式（类型化数组）交给 JS，不用 wasm-bindgen（少一个工具链，不需要 JS 胶水代码生成）。界面侧 `src/engine/wasm.ts` 加载 `verity_core.wasm`（构建产物随源码提交，构建时校验哈希），在现有 Worker 中运行，对外接口与 `SimulationRun` 相同。WASM 加载失败（极老的浏览器、策略禁止）时退回 TypeScript 引擎并在“场景”页标明。WebView2 和 Chromium 都支持 WASM；网页包无需额外响应头。构建：Windows 上 `rustup target add wasm32-unknown-unknown` + `cargo build -p verity-wasm --release --target wasm32-unknown-unknown`，`release.cmd` 增加这一步与哈希校验。

**D30 Rust 与 TypeScript 逐位一致的规则。** WebAssembly 的 f64 运算遵循 IEEE 754，四则运算与 sqrt 正确舍入，只有 NaN 的位模式不确定；Rust 默认不融合乘加（不自动生成 FMA）。因此只要运算顺序相同，结果就逐位相同。规则：(1) 超越函数一律用移植的 `dmath`（与 TS 同一算法），禁用 `f64::sin/cos/exp/powf` 等标准库实现；(2) 复刻 JS 语义的小函数：`js_min/js_max`（−0 与 NaN 的处理同 `Math.min/max`）、`js_round`、整数与浮点转换；(3) 不用迭代顺序不确定的容器（`HashMap` 换成 `Vec` 或 `BTreeMap`/插入顺序表），排序用稳定排序且比较规则与 TS 相同；(4) 求和顺序、循环顺序逐行对照 TS；(5) NaN 一律视为错误并停止，不让 NaN 位模式进入指纹；(6) 不开启 relaxed SIMD。验证：容器内用原生 Rust（x86_64）跑同一测试集，与 Node 中的 TS 结果逐位比较；Windows 上在 WebView2 中比较 WASM 与 TS 的指纹。原生与 WASM 同源、同语义，三方一致即视为通过。

**D31 TypeScript 求解器的去留。** 26.50 中 TypeScript 求解器保留为：(a) 测试对照（每次测试都与 Rust 逐位比较）；(b) WASM 不可用时的后备。新功能（D26 的流式记录）两边都实现，以保证对照有效。26.51 起新的物理功能只在 Rust 中实现，TypeScript 求解器冻结为 26.50 的能力，作为后备时会提示“部分功能需要 WASM 引擎”。

**D32 长时间曲线。** 曲线数据由块摘要（D26）和热区帧组成：缩放到全程时画每个像素列的最小/最大包络；放大到热区时画原始帧；不在内存中的块按需从检查点重算（在计算线程中，不阻塞界面）。播放时默认显示“最近 10 s”滑动窗口，可切换为全程。

**D33 频闪照片。** 频闪是记录的另一种画法，不是新数据：在 t − n·τ（n = 1…N）时刻用精确状态画出半透明的物体轮廓（τ 默认 0.1 s，N 默认 10），透明度递减，可选显示时刻标签。导出时与画面一致。

- 停止条件：“到 2.5 s 停止”与 26.49 指纹相同；`stopAt` 在事件后正确时刻停止（`tests/streaming.test.ts`）。
- 三语言：1790 条文字齐全；英文、德文界面扫描只剩语言名“简体中文”。

**偏差与原因：**

1. **D27 文本表的形式。** 没有做成以嵌套键组织的 `zh.ts / en.ts / de.ts`，而是以中文原文为键的 gettext 式表（`tl('保存')`，`src/i18n/texts/*.ts`）。原因：1700 多条现有文字分散在 90 多个组件里，以原文为键可以逐文件机械替换、不引入命名错误；缺键、多键、占位符不一致和译文含中文由 `tests/i18n.test.ts` 与 `scripts/i18n-keys.mjs`（静态提取）检查，效果等同类型检查。模块级常量表用 `trDeep` 代理在读取时翻译。复数形式没有用到（中文、英文、德文的现有文字都用“数字 + 单位”写法）。
2. **D27 德文小数逗号、导出单独选语言** 未做：数字一律用小数点；导出跟随界面语言。移入 26.51。
3. **D32 重算位置。** 被释放的块在界面线程中用 TypeScript 引擎同步重算（每块约 10 ms，核对块摘要后才使用），不是在计算线程中。原因：重算必须与原计算逐位相同，界面线程上的 TS 引擎已有逐位保证，且 10 ms 不造成可感知的卡顿；移到计算线程需要请求 / 应答协议与缓存，移入 26.51。
4. **静止检测** 采用严格判据（所有导数严格为零），渐近静止不会自动停止，由前瞻窗口限制计算量。阿特伍德机、桌面—滑轮连接体不限时长时，物块到达滑轮后以“步长过小”停止（26.49 同样的模型限制），26.51 增加“到达滑轮”事件。
5. **D31** 按计划：TypeScript 求解器在 26.50 保持全部功能，26.51 起冻结。
